AI 운동 메모 파싱 파이프라인 openai · RAG

문제
사용자가 자유롭게 쓴 메모("랫풀다운 70 80 80 / 8-12reps")를 운동·세트 구조로 저장해야 했습니다. LLM에 그대로 맡기면 DB에 없는 운동명을 지어내거나 JSON이 깨졌습니다.
접근
운동종목을 OpenAI 임베딩으로 벡터화해 PostgreSQL pgvector에 저장(주 DB와 데이터소스 분리). 메모를 줄 단위로 정규화(숫자·단위 제거)해 임베딩하고 코사인 거리로 후보를 추린 뒤, 그 후보 목록만 프롬프트에 주입해 LLM이 목록 안에서만 매칭하도록 제약했습니다. system/user 메시지를 분리해 순수 JSON을 강제.
결과
자유 서술 → 구조화 데이터 자동 변환. 입력은 이메일·전화 마스킹 + SHA-256 해시로 로깅해 실패 케이스를 추적합니다.

영상 스트리밍 — Kollus 연동에서 자체 파이프라인으로 kollus → aws · learning

구현
강의 영상을 외부 플랫폼 Kollus로 서빙. 업로드·삭제·LMS·재생 콜백 4종을 구현하고, 재생 콜백의 kind 값에 따라 응답 구조가 달라 kind별 DTO로 분기. 회원별 UserKey와 전용 JWT로 보안 스트리밍 URL을 발급하고 KollusMediaLink로 시청 진행률을 추적했습니다.
이관
팀이 구축한 자체 AWS 파이프라인(S3 멀티파트 업로드 + CloudFront HLS)으로 옮겨가면서, 강의 도메인이 영상을 Kollus 대신 AWS 미디어에서 받아오도록 엔티티·서비스·응답 DTO를 전면 교체했습니다. Lecture의 Kollus 연관관계를 제거하고, 강의별 CDN URL 제공 API(GET /lecture/{id}/media, 이전/다음 강의 정보 포함)를 신설.
진행률 재설계
Kollus 콜백이 사라지며 깨진 진행률 로직을 걷어내고, LearningProgress · LearningProgressEvent 엔티티와 클라이언트 보고형 API(POST /lecture/{id}/progress)로 새로 설계했습니다. 되감아도 최대 진도율은 줄지 않고 한 번 완강한 강의는 롤백되지 않도록 정책을 엔티티에 캡슐화하고, 클래스룸·수강의 진도 집계를 여기에 맞춰 재작성.

AWS 계정 이관 · 인프라 재구축 infra

배경
AWS 프리티어가 만료되며 비용 구조를 바꿔야 했고, 신규 계정으로의 이관을 단독으로 담당했습니다.
이관
기존 인프라 구성(EC2 · RDS · S3/CloudFront · IAM)을 신규 계정에 재구축하고, RDS 덤프·복원과 S3 오브젝트 동기화, 애플리케이션의 접속 정보 · CDN 도메인 · 자격 증명 교체까지 수행했습니다. 이 과정에서 서비스 인프라 전 구간의 구성을 직접 파악·운영했습니다.
다음 단계
현재 배포는 수동 스크립트 방식으로, 이관 시 다운타임이 길었던 경험을 바탕으로 GitHub Actions 기반 CI/CD와 무중단 배포 도입을 계획하고 있습니다.
